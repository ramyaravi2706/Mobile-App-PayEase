# CODTECH – Task 3
# Mobile App Heuristic Evaluation

## 1. Project Details

- **Project Name:** PayEase – Fintech Mobile Application
- **Internship Domain:** UI/UX Design
- **Task:** Mobile App Heuristic Evaluation
- **Design Tool:** Figma
- **Evaluation Method:** Nielsen's 10 Usability Heuristics
- **Evaluation Type:** Screenshot-based heuristic evaluation

## 2. Introduction

PayEase is a conceptual fintech mobile application designed to provide users with a simple and convenient digital payment experience.

The application consists of four main screens:

1. Onboarding Screen
2. Home Screen
3. Search Screen
4. Payment Details Screen

This evaluation examines the usability and interface design of these screens using Nielsen's 10 Usability Heuristics.

## 3. Evaluation Objectives

- Identify potential usability issues.
- Evaluate interface consistency and navigation.
- Examine the clarity of information and visual elements.
- Recommend improvements to enhance user experience.
- Assess the overall usability of the PayEase interface.

## 4. Nielsen's 10 Usability Heuristics Evaluation

### 1. Visibility of System Status

**Observation:** The Payment Details screen displays a green success icon, payment status, amount and transaction information.

**Positive Aspect:** Users can easily recognize that a payment has been completed.

**Recommendation:** Maintain clear and immediate transaction status feedback.

**Severity:** 0 – No usability issue observed.

### 2. Match Between System and the Real World

**Observation:** Familiar terms such as Send Money, Receive Money, Recent Transactions and Search Contacts are used.

**Positive Aspect:** The terminology is easy for users to understand.

**Recommendation:** Continue using simple, familiar financial terms.

**Severity:** 0 – No usability issue observed.

### 3. User Control and Freedom

**Observation:** Back and Home icons are visible on the Search and Payment Details screens.

**Potential Issue:** The Payment Details screen does not display the same complete bottom navigation available on the Home and Search screens.

**Recommendation:** Provide consistent navigation options and ensure users can return to the Home screen easily.

**Severity:** 1 – Cosmetic usability issue.

### 4. Consistency and Standards

**Observation:** The application uses a consistent purple colour theme, typography style and visual design.

**Potential Issue:** The bottom navigation is not displayed consistently across all screens.

**Recommendation:** Maintain consistent navigation placement, icon styles, button sizes and spacing.

**Severity:** 1 – Cosmetic usability issue.

### 5. Error Prevention

**Observation:** The provided screens do not show a payment confirmation step before completing a transaction.

**Potential Issue:** Users may accidentally initiate an incorrect payment if confirmation is not provided in the actual payment flow.

**Recommendation:** Add a payment review and confirmation screen displaying the recipient, amount and payment method before submission.

**Severity:** 2 – Minor usability concern; requires flow verification.

### 6. Recognition Rather Than Recall

**Observation:** The Search screen displays recent contacts, recent searches and suggested services.

**Positive Aspect:** Users can recognize frequently used contacts and services without remembering their details.

**Recommendation:** Continue providing recent contacts, recognizable icons and clear labels.

**Severity:** 0 – No usability issue observed.

### 7. Flexibility and Efficiency of Use

**Observation:** Quick actions such as Send Money, Receive Money, Scan QR and Pay Bills are available on the Home screen.

**Positive Aspect:** Frequently used services are easily accessible.

**Recommendation:** Consider adding favourite contacts and frequently used payment shortcuts.

**Severity:** 0 – No major issue observed.

### 8. Aesthetic and Minimalist Design

**Observation:** The application uses a clean layout with a purple-and-white colour theme.

**Potential Issue:** Some transaction information on the Payment Details screen appears relatively small.

**Recommendation:** Improve text readability by increasing font size, spacing and contrast where necessary.

**Severity:** 1 – Cosmetic usability issue.

### 9. Help Users Recognize, Diagnose and Recover from Errors

**Observation:** Error messages and failed-payment recovery screens are not included in the provided four-screen design.

**Potential Issue:** Users may not know what to do if a payment fails or remains pending.

**Recommendation:** Provide clear error messages, transaction status explanations and retry options.

**Severity:** 2 – Minor usability concern; error-flow verification required.

### 10. Help and Documentation

**Observation:** A dedicated Help or Support option is not visible in the provided screens.

**Potential Issue:** Users may have difficulty finding assistance when facing payment-related problems.

**Recommendation:** Add an accessible Help Centre, FAQs and customer support option.

**Severity:** 1 – Cosmetic usability issue.

## 5. Severity Rating Scale

| Rating | Description |
|---|---|
| 0 | No usability issue |
| 1 | Cosmetic issue |
| 2 | Minor usability issue |
| 3 | Major usability issue |
| 4 | Usability catastrophe |

## 6. Overall Recommendations

1. Maintain consistent navigation across all screens.
2. Improve the readability of transaction information.
3. Include payment review and confirmation before transactions.
4. Design payment failure and recovery states.
5. Provide an easily accessible Help and Support section.
6. Maintain consistent colours, typography and interface elements.

## 7. Conclusion

The PayEase mobile application presents a simple and visually consistent fintech interface. The four screens provide essential elements such as onboarding, account balance, quick payment actions, contact search and payment confirmation.

The heuristic evaluation identifies opportunities to improve navigation consistency, transaction readability, error prevention and user support.

Implementing these recommendations can improve the usability, accessibility and overall user experience of the PayEase application.

## 8. Tools Used

- Figma – Mobile UI design and prototype.
- Nielsen's 10 Usability Heuristics – Usability evaluation.

## 9. Evaluation Limitation

This evaluation is based on the four provided Figma screen designs. It is not a live application usability test. Payment confirmation behaviour, error recovery, navigation interactions and accessibility compliance require additional prototype or application testing.
